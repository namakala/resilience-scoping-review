# Model Integration and Retrieval Architecture

Two machine learning models were integrated into the analysis pipeline: a sentence-transformer for semantic embedding and a large language model served through the Groq cloud API [@groq2024api]. The embedding model, all-MiniLM-L6-v2, produced 384-dimensional L2-normalised vector representations and was loaded as a thread-safe lazy singleton with CPU-only inference [@reimers2019sentencebert]. The model was instantiated once at first use and cached for the duration of the process, with explicit lifecycle management functions available to clear the in-memory state and optionally remove the local Hugging Face Hub cache. This design ensured predictable memory usage suitable for execution on a laptop with eight gigabytes of RAM.

The Groq API client was configured as a synchronous singleton with configurable timeout and maximum retry parameters. All LLM calls used a temperature of zero and requested structured JSON output matching predefined Pydantic schemas [@colyer2021pydantic] for codes, themes, and interpretations. The client constructed messages by combining system instructions (containing role definition, output schema, and analytical rules), few-shot demonstration pairs loaded from curated JSON files, and user messages containing the batch data with ontology context. This three-part message structure grounded every LLM response in the existing tag hierarchy and expected output format without requiring fine-tuning.

The hybrid retrieval architecture combined three distinct similarity signals to support all inference and review operations. Graph-based scope restriction first limited candidate pools to the ontology subtree of the query tag, ensuring retrieval respected the taxonomical structure of the research domain. BM25 lexical retrieval captured exact term overlap using the precomputed keyword index, while embedding-based cosine similarity retrieved semantically related entities using the cached vector representations. A final reranking stage computed a weighted sum of these three scores using empirically determined weights.

The retrieval weights were configurable by entity type: exemplar queries used embedding similarity weighted at 0.5, ontology proximity at 0.3, and BM25 lexical score at 0.2, while non-exemplar queries renormalised to omit the BM25 component. Neighbour discovery for review context used cosine similarity within the same tag scope with a minimum threshold of 0.5, results cached with a five-minute time-to-live during interactive sessions to avoid redundant recomputation. The combined system provided ontology-aware semantic search across exemplars, codes, themes, and interpretations with typical query latency of approximately ten milliseconds.
