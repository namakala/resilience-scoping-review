# Keyword Extraction, Semantic Indexing, and Knowledge Graph Construction

Keywords were extracted from each exemplar using the KeyBERT library [@grootendorst2020keybert] with Maximal Marginal Relevance (MMR) to promote diversity among the selected key phrases. The top-five keywords were retained per exemplar with a diversity parameter of 0.5 and an n-gram range of one to two words, using the same underlying sentence-transformer model as the embedding layer to avoid redundant model loading. Each exemplar and its extracted keywords were encoded into 384-dimensional vector embeddings using the sentence-transformer model all-MiniLM-L6-v2 [@reimers2019sentencebert], with L2 normalisation and CPU-based inference. Embeddings were stored in a DuckDB-backed cache [@raasveldt2019duckdb] keyed by entity identifier and content hash; immutable entities (exemplars and keywords) were cached indefinitely, while mutable entities (codes, themes, interpretations) triggered cache recomputation only upon content changes.

A BM25 lexical index was constructed over the keyword corpus using the rank_bm25 library [@trott2022rankbm25] to complement semantic retrieval with exact term matching. The tokenisation pipeline was configurable and applied lowercasing, punctuation stripping, whitespace splitting, and stopword removal in sequence. The index was serialised to disk with a corpus hash for staleness detection. Hybrid retrieval combined BM25 lexical scores, cosine similarity from cached embeddings, and ontology proximity measured as inverse depth difference between tags. Weights were configured at 0.5 for embedding similarity, 0.3 for ontology proximity, and 0.2 for BM25 lexical score, with candidate pools first restricted to the relevant ontology subtree via graph traversal.

A heterogeneous knowledge graph was constructed to represent all semantic entities and their structural relationships. The tag ontology was loaded from CSV and built as a directed acyclic graph using the NetworkX library [@hagberg2008exploring], with parent-child edges defining the hierarchy and graph-based depth computed as shortest path length from root nodes. Codes, themes, and interpretations were stored as typed nodes in a DuckDB database, with edges encoding semantic relationships including contains (code-to-exemplar evidence linkage), composed-of (theme-to-code aggregation), spans (interpretation-to-theme coverage), derived-from (evolution chains for revision tracking), and neighbor (similarity links for review context). An in-memory NetworkX mirror was constructed from the DuckDB tables at startup to enable fast graph traversal and path queries without repeated database access.

The knowledge graph was updated incrementally through explicit synchronisation operations that kept the in-memory NetworkX mirror consistent with the DuckDB persistent store after each node or edge mutation. Materialised traversal caches (ancestors, descendants, and subtree aggregate exemplar, code, and theme identifiers) were precomputed for every tag and persisted as JSON arrays in DuckDB to accelerate repeated subtree queries during interpretation synthesis. Ontology changes triggered cascade invalidation of these caches for the affected tag and all its descendants, with stale flags recorded in an audit log. A dirty-state propagation mechanism tracked which ontology branches required recomputation, ensuring that downstream inference stages processed only tags with pending changes and avoided full graph reconstruction.
