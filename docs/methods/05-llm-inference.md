# LLM-Based Thematic Inference

All LLM inference was conducted in batches to balance token cost, analytical quality, and API rate limits. Batches were formed by grouping inference items by their parent ontology tag, sorting by identifier for determinism, and splitting any tag exceeding fifteen items into multiple batches. Each batch carried metadata including the tag, batch index, total batch count, and a unique batch identifier for traceability. For code inference specifically, exemplars within a tag were further clustered by pairwise embedding similarity using a configurable threshold (default 0.6) with transitivity-based union-find grouping, so that each cluster formed a single batch producing one abstract code.

Prompts were constructed as structured bundles with three components: system instructions defining the LLM role, analytical rules, and the required JSON output schema; few-shot demonstration pairs loaded from curated JSON files to steer output format and granularity; and user messages containing the batch data enriched with ontology context including the tag path, tag description, and existing approved codes or themes. Three distinct prompt bundles were designed for code inference (exemplars to codes), theme inference (codes to thematic groupings), and interpretation synthesis (themes across tags to cross-cutting insights). The few-shot demonstrations were configurable in count (default two) and optional shuffling, with a future mechanism to dynamically retrieve previously approved examples as the corpus accumulated.

LLM responses were stripped of markdown fences, parsed as JSON, validated against Pydantic schemas [@colyer2021pydantic] specific to each inference type, and unwrapped from top-level array keys such as codes, themes, or interpretations. Validation failures raised descriptive parse errors, while extra fields were logged as warnings without blocking pipeline progression. A three-tier retry strategy handled infrastructure failures: network timeouts and connection errors retried with exponential backoff (maximum three attempts), HTTP 429 rate limits triggered a sixty-second pause before a single retry, and token-limit errors caused automatic batch splitting with recursive reprocessing of each half.

Inference proceeded through three hierarchical stages corresponding to increasing levels of abstraction. Code inference mapped exemplar evidence to named patterns within each tag, producing grounded analytical units linked directly to source excerpts. Theme inference grouped approved codes within each tag into broader thematic narratives, enforcing the constraint that all codes in a theme share the same parent tag. Interpretation synthesis operated across tags, aggregating approved themes into cross-cutting insights that spanned multiple ontology branches. Token usage was recorded per call and aggregated across stages, with configurable cost thresholds that warned when stage expenditure exceeded a predefined limit.
