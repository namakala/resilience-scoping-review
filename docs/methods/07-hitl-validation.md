# Human-in-the-Loop Validation

Human-in-the-loop validation was embedded at three critical junctures of the analysis pipeline: after code inference, after theme inference, and after interpretation synthesis. At each juncture, the system presented pending candidates to the researcher through an interactive terminal interface built with the Textual library [@willmott2022textual]. Each review item was displayed alongside supporting context including the source exemplar excerpts, extracted keywords, ontology tag path, the LLM-generated rationale, and similar existing entities discovered through embedding similarity. This contextual presentation enabled the researcher to evaluate each candidate against the original evidence before making a validation decision.

The researcher could perform six atomic actions on each review item: approve (mark as validated and propagate downstream), edit (modify the name or definition and reset status to draft), merge (combine two entities into one and reroute all evidence links), reject (mark as unsound and exclude from downstream inference), split (partition an entity into multiple new candidates with LLM re-inference for each group), and defer (skip for later review while preserving the draft status). Each action was validated against the ontology constraint rules before execution, and constraint violations produced descriptive error messages explaining which rule was breached. All actions were recorded in a user action log table with timestamps for complete audit trail traceability.

An undo and redo system supported reversible decision-making throughout the validation workflow. The action history stack stored each user action in chronological order, and undo operations reversed the most recent action by restoring the previous graph state and clearing affected dirty flags. Redo reapplied a previously undone action, and both operations were validated against the constraint rules before execution to prevent illegal state transitions. The history depth was bounded only by the session lifetime, allowing researchers to explore alternative analytical paths without permanent consequences.

State mutations from review actions propagated through the dirty-state mechanism to trigger downstream recomputation where necessary. Code approval enabled theme inference for its parent tag; theme approval enabled interpretation synthesis for the spanned tag subtree; edits to definitions or narratives invalidated the embedding cache for the affected entity. This invalidation cascade ensured that the analytical outputs remained consistent with the validated evidence base while avoiding full recomputation of unaffected ontology branches. The researcher could exit and resume the review session at any point, with all pending and completed actions preserved in the session state.
